# Unlock English 0.3 — плавный интерфейс и звуковой отклик

Квизы A1–B2, письмо, ежедневная миссия и ИИ-разбор из 0.2 сохранены. Добавлены движение, локальные звуки и экран завершения миссии.

**Важно:** это исходники и запускаемая на компьютере веб-/backend-итерация. Нового Android APK в этой версии нет. В `original/` лежит только предоставленный ранее APK 0.1. Не удаляй установленное приложение ради этого архива.

## Что нового в 0.3

- Переходы между разделами, поочерёдное появление блоков, плавное открытие/закрытие окон, отклик кнопок и переключателей, движущийся индикатор навигации.
- Верный ответ: короткий восходящий сигнал и зелёный отклик. Ошибка: мягкий нисходящий сигнал, короткое смещение карточки и объяснение.
- После квиза — небольшая анимация результата. После **обоих** шагов дневной миссии — похвала, конфетти, короткая мелодия, фактический бонус +20 XP и серия дней. Повторное сохранение, возвращение на главный экран и восстановление состояния не повторяют праздник и награду.
- Кнопка **«Звук и эффекты»** (значок ползунков вверху) открывает переключатели звука/движения, громкость и прослушивание трёх сигналов. «Посмотреть анимацию» показывает демо без изменения прогресса.
- Звуки синтезируются через Web Audio: нет внешних файлов, загрузок и фоновой музыки. Инициализация происходит после взаимодействия, а не при открытии страницы. При уходе вкладки в фон звуки останавливаются; мелодии не накладываются друг на друга.
- Уменьшение движения в настройках устройства имеет приоритет. Даже без Web Audio/Web Animations или при запрете локального хранилища учебная логика продолжает работать. При запрете хранилища нельзя обещать сохранение между сессиями.

Настройки эффектов лежат отдельно в `unlock-english-ux-v1`; учебный прогресс остаётся в `unlock-english-v1`. При обновлении сайта на том же origin прогресс не мигрируется и не сбрасывается. **Для локальных HTML-файлов с разными именами общность хранилища не гарантируется:** перед сменой файла воспользуйся экспортом/импортом в разделе «Прогресс».

## Запустить без ИИ

Требуется Node.js 22.6 или новее. В терминале из корня папки:

```sh
npm start
```

Открой адрес из терминала — по умолчанию `http://127.0.0.1:4173`. Установка npm-зависимостей не нужна: сервер написан на встроенных модулях Node.js.

Работают квизы, письменные темы, сохранение черновиков, локальная самопроверка и **фиксированный демо-пример** разбора. В разделе «Тексты» нажми «Посмотреть демо». Это не проверка введённого тобой эссе; она не обращается к модели и не влияет на прогресс.

Для просмотра без Node есть `dist/Unlock-English-0.3-preview.html`. Открой файл в браузере с поддержкой JavaScript. Это автономный HTML-просмотр: сеть отключена, настоящей ИИ-проверки и Android-блокировок там нет. Хранение данных при открытии локального файла зависит от браузера; не используй его как единственное хранилище важных текстов.

## Включить настоящую ИИ-проверку

1. Скопируй `.env.example` в `.env` (Windows: `copy .env.example .env`, PowerShell: `Copy-Item .env.example .env`, macOS/Linux: `cp .env.example .env`).
2. В `.env` укажи свой серверный `OPENAI_API_KEY` и доступную в твоём API-проекте модель. Поставь `AI_ENABLED=true`.
3. Перезапусти `npm start`.
4. Открой «Тексты → Подключение ИИ». Введи **Local access token из терминала**, НЕ ключ OpenAI. Этот токен создаётся у тебя при первом запуске; в архиве его нет.
5. Напиши текст → «Проверить текст» → прочитай уведомление о данных и подтверди отправку.

Пример настроек (не настоящий ключ):

```dotenv
AI_ENABLED=true
OPENAI_API_KEY=YOUR_SERVER_SIDE_KEY
OPENAI_MODEL=gpt-5.4-mini
OPENAI_REASONING_EFFORT=none
AI_DAILY_LIMIT=20
```

`gpt-5.4-mini` указан как документированный пример с поддержкой Structured Outputs и reasoning effort `none`, не как модель, проверенная здесь живыми запросами. Модель меняется конфигурацией. Если выбираешь другую, проверь её поддержку Responses API, JSON Schema и reasoning effort; последнее можно оставить пустым.

API-запросы имеют собственный биллинг; этот проект не использует ChatGPT/Codex-вход как оплату модели. **Не присылай API-ключ в чат и не вставляй его в приложение.** Он нужен только серверу. Не коммить `.env`, `.local/` и токены.

## Сохранённые возможности ИИ из 0.2

- Понятные карточки «было → исправление → объяснение», примеры и сравнение двух текстов.
- Стиль отделён от ошибок; оценки 0–10 учебные, не IELTS/CEFR. Для короткого текста модель получает инструкцию не придумывать точную оценку.
- История ИИ-разборов привязана к конкретной версии текста. Ответ на старую версию не прикрепляется к изменённому черновику.
- Темы ошибок связываются с существующим банком. Есть отдельная практика; до двух подходящих вопросов включаются в следующую ещё не созданную миссию.
- Повторное сохранение того же текста в тот же день больше не дублирует историю. Правки сохраняются отдельными версиями; XP не удваиваются.
- Явное согласие на каждую отправку; отмена ожидания, обработка ошибок, офлайн-самопроверка.
- Идемпотентность в пределах процесса сервера, строгая проверка JSON и цитируемых фрагментов, токен доступа, ограничения частоты и дневной квоты.

**ИИ не завершает миссию и не разблокирует приложения.** Дневной сценарий продолжает использовать локальную учебную логику. Отсутствие сети, ключа или квоты не запирает пользователя.

## Данные, стоимость и ограничения сервера

Сервер рассчитан на одного владельца и запускается только на `127.0.0.1`. По умолчанию 5 новых запросов в минуту и 20 попыток в сутки UTC. Даже неуспешная попытка расходует локальный лимит: провайдер мог начать обработку. Автоматических платных повторов нет.

Счётчик сохраняется в `.local/budget.json` и не сбрасывается при обычном перезапуске. Это лимит числа попыток, а не точный денежный потолок. Настрой и лимиты расходов в API-проекте. Используй один процесс сервера; горизонтальное масштабирование и несколько пользователей не поддерживаются.

Текст эссе и тема уходят на свой backend, затем в OpenAI. История занятий и список Android-приложений не передаются. Сервер не пишет тексты в логи/на диск; до 32 результатов могут храниться в оперативной памяти до 30 минут или до перезапуска. После перезапуска кэш пропадает, повторный запрос может вызвать новое платное обращение. Данные провайдера обрабатываются по его правилам; `store:false` не является обещанием нулевого хранения у провайдера.

Разборы и черновики хранятся локально в учебном состоянии. В экспорт входят тексты и разборы; относись к резервной копии как к личным данным. Токен backend хранится в sessionStorage и не экспортируется. Удали `.local/access-token.txt` и перезапусти сервер для смены автоматически созданного токена. При явно заданном `APP_ACCESS_TOKEN` смени его в `.env`.

Отмена в интерфейсе останавливает ожидание браузера, но не гарантирует отмену уже начатого платного запроса. Повтор такой же отправки в работающем процессе объединяется с текущим запросом или использует кэш.

**Не публикуй этот локальный dev-сервер в интернет.** Для телефона и публичного HTTPS backend нужен отдельный этап: адрес сервера, безопасная авторизация, список разрешённых источников, HTTPS-прокси, эксплуатационные лимиты. В текущей реализации запросы идут только на тот же origin. Старый APK с file:// WebView не может использовать этот backend без доработки.

## Структура

```text
web/                  UI, учебная логика, ux.js и motion.css
backend/              личный Node.js backend и адаптер OpenAI
original/web/         неизменённые первоначальные assets
original/*.apk        исходный APK 0.1 — НЕ новый билд
android-binary/       сохранённые DEX/ресурсы
tests/               автоматические тесты и явные фикстуры
tools/               проверка, preview, инструменты восстановления
dist/                автономный HTML-просмотр
docs/                отчёты, контракт и ограничения
```

## Проверки

```sh
npm test
npm run check
npm run build:preview
python tools/verify-extraction.py
```

Тесты используют фиктивный провайдер/ответы, а не твой API-ключ. `tests/ui-controller.test.cjs` проверяет контроллер с DOM-заглушками; `tests/ux.test.cjs` — звуковые события и настройки. Дополнительно выполнен `tests/browser-smoke.py`: изолированный Chromium, настоящие DOM/CSS/Web Audio, но хранилище подставлено в память. Навигацию на localhost/file среда блокирует; тест не отключает эти ограничения и загружает разрешённый автономный HTML прямо в тестовый документ. Это не проверка Android WebView и не слуховая оценка через динамик телефона. Скрипту нужны Python Playwright и Chromium; Node-тестам дополнительные зависимости не нужны.

Что действительно проверено и что не удалось проверить: `docs/TEST_REPORT_0.3.md`.

## Следующий этап Android

Нужно восстановить Java-оболочку и Gradle-проект, безопасно подключить сеть, настроить HTTPS-связь с backend и собрать APK. Исходный манифест не содержит INTERNET. Ключ подписи исходного APK неизвестен — установка поверх него и сохранение данных пока не проверены. Экспортируй прогресс перед любыми будущими переустановками.

AccessibilityService и ограничения приложений в этой итерации не изменялись и не проверялись на устройстве. В браузере они не работают. Не включать universal file:// access или внедрять провайдерский ключ в WebView ради быстрого подключения.
